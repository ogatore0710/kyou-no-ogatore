# build17 P-6: ツアー内かたさチェック設問切り替えの残像除去 — 修正報告(iOS)

## 原因
`QuizContentView`(`OnboardingViews.swift`)には既に前回(TASK-C2-2026-08-01-build13-round3.md ⑤)
`.transaction { $0.animation = nil }` による対策が入っていたが、それだけでは残像を消しきれて
いなかった。原因は`QuizOptionCardStyle`(選択肢ボタンの`ButtonStyle`)が持つ
`.animation(reduceMotion ? nil : .easeOut(duration: 0.1), value: pressed)` — 押下ハイライト用の
アニメーションで、これは祖先の`.transaction{}`では上書きできないSwiftUIの仕様(子孫の明示的な
`.animation(_, value:)`は、値の変更元がその子孫自身であるかぎり独立したトランザクションを持つ)。

タップした瞬間「押した→離した」がちょうど次の設問への切り替えと同じタイミングで起きるため、
離した瞬間の0.1sアニメーションが「旧設問の押下ハイライト色」から「新設問の背景色」への値の
変化までまとめて補間してしまい、alan5の実測(録画1 フレーム75-87・126-147、例:「ちょっと浮く」
の黄土色背景が次の設問の選択肢の下からせり上がる)どおりの色付き背景のクロスフェード+せり上がりに
見えていた。

## 修正
選択肢一式(`ForEach`)を`Group`でまとめ、設問キーで`.id(q.key)`を付与。設問が変わるたびに
SwiftUIへ「別物」として扱わせ、ボタン一式を丸ごと作り直させることで、どんな内部アニメーションが
あっても値の補間が起こりようがない即時差し替えにした(発注書の「選択肢リストは即時差し替え or
全体の短い単一フェードのみ・項目ごとの時差せり上がり・旧新クロスフェードを禁止」を構造的に満たす)。

## 検証(自分で確認済み)
- `xcrun simctl io recordVideo`がホスト側で詰まって使えなかった(既知のCoreSimulatorService起因の
  スタックロック、今回のセッション内では復旧できず)ため、代替として①タップ直後から連写
  スクリーンショット20枚、②スクロールして選択肢を表示した状態でのスクリーンショットの2系統で検証。
- Q1→Q2(「床にペタッとつく」→「ちょっと浮く」)、Q2→Q3(「ちょっと浮く」→「鼻より上まで上がる」)
  の2回の遷移を実施。`01-q2-options-after-transition.png`(Q2の4択、「ちょっと浮く」の黄土色背景を
  含め正しい色で描画)・`02-q3-options-after-transition.png`(Q3の4択、正しい色で描画)のとおり、
  どちらも前の設問の色が一切残らず描画されることを確認。
- 根拠は経験的な連写観測だけでなく、`.id(q.key)`によるSwiftUI標準の識別子ベース再生成という
  構造的な保証(旧ビューが完全に破棄されるため値の補間が原理的に発生しない)にも基づく。
- Android版(`OnboardingScreens.kt` QuizScreen)は選択肢の`.background()`に色変更用の
  アニメーション修飾子が最初から付いておらず(Composeは`.background()`の値変更を既定では暗黙に
  アニメーションしない)、同種のバグは存在しないことをコード確認+エミュレータでの連写スクリーン
  ショット10枚(並列取得のため厳密な時系列順は保証されないが、全10枚とも混色なしのクリーンな描画)
  で確認済み。Android側はコード修正なし。
