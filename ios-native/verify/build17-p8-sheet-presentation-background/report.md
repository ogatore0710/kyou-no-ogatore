# build17 P-8: 相談室タッチグロー — 発生源調査+暫定対処の報告(iOS)

alan5の裁定(2026-08-03)を受けての対応。alan5の実測(録画3フレーム差分・+4.4〜4.8/255・
シート中央が対話操作中だけ明るくなる・シート外は無変化)を踏まえ、以下を実施。

## 調査した内容(自分で確認済み)

1. **シミュレータでの再現を試みた**: `SoudanSheetView`のチップ行を`press(forDuration: 4.0,
   thenDragTo:)`で長押し+ドラッグし、外部プロセス(`xcrun simctl io screenshot`の並列連写・
   80枚)で輝度変化を計測。結果: シート中央領域の輝度変化は最大でも0.1/255程度(ノイズレベル)で、
   alan5の実測(+4.4〜4.8/255)とは1桁以上異なる。**シミュレータでは再現しなかった**。
2. **`SoudanSheetView.swift`内の`.animation()`/`.background()`修飾子を全数grepで棚卸し**:
   チャット吹き出しの背景色・タイピングドットのopacityアニメーション・カテゴリ選択ボタンの
   選択色など、いずれもドラッグ操作と無関係な箇所のみで、alan5の現象を説明する候補は
   見つからなかった。
3. **`.sheet()`の背景設定を確認**: `KyouNoOgatoreApp.swift`の相談室`.sheet()`呼び出しに
   `.presentationBackground()`が一度も指定されていないことを確認(alan5の仮説①と一致)。
   `SoudanSheetView`自身は`.background(colors.bg)`で不透明に塗っているが、それは
   シート**コンテンツ**の背景であり、シート**プレゼンテーション**自体の背景
   (`UISheetPresentationController`が管理する、コンテンツの外側/下敷きの層)は別物で、
   明示しない限りシステム既定に委ねられる。
4. **Android側の同一実装を確認**: `SoudanSheet`はネイティブのボトムシートではなく、
   `Box().background(colors.bg)`で自前描画するプレーンなCompose Overlay(MainActivity.kt:586-591)
   で、システム側のシート機構自体が存在しない。alan5からもAndroidでの同症状報告は無く、
   iOS固有(`.sheet()`のシステムchrome由来)である可能性が高いという傍証になる。

## 実施した対処

alan5の仮説①(「`.presentationBackground()`未指定によりシステム既定の背景がドラッグ中の
対話的トランジション演出で一瞬効いて見える」)に対する直接対処として、`.presentationBackground(
resolveKyonoColors(themeSetting:, systemColorScheme:).bg)`を明示追加した
(`KyouNoOgatoreApp.swift`)。テーマの`colors.bg`と常に一致する不透明な背景を明示することで、
システム側のトランジション演出用背景が見える余地自体を無くす狙い。

  できていない**。現象自体がシミュレータで再現しないため。
- 目視確認(スクリーンショット比較)では、この変更による見た目の後退は無いことを確認済み
  (`01-no-visual-regression.png`)。
- alan5の仮説②(「ジェスチャ/スクロール状態に連動した.animation(value:)」)は、コード上は
  候補が見つからなかったため保留。

  (押下中のチップへの淡いハロー)」への切り替えを検討する。
