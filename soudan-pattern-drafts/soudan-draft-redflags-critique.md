## 2. 誤検知（false positive）リスク

| # | 提案kw | 深刻度 | 問題 |
|---|---|---|---|
| 2-1 | **`しっしん`（#2）** | **致命的** | ひらがな「しっしん」は**湿疹**と同綴り。sdNormはカタカナ→ひらがな変換するので「シッシン」も同様。「しっしんがかゆい」等の皮膚相談が**症状系・今すぐ受診**に飛ぶ。漢字「失神」のみ残し、ひらがな形は削除必須。 |
| 2-2 | **`目の前が真っ暗`（#4）** | **高** | 絶望の慣用句（「将来を考えると目の前が真っ暗」）。本アプリはstress/不安系intentとcrisis判定を持ち、メンタル相談の入口になっている。落ち込みの訴えに「眼科へ」と返す事故は、単なる誤爆でなく**心情の否認**になる。crisis判定はredFlagsより先だが、crisis kwは「死にたい」等の直接語のみで、この慣用句はcrisisを通過してこの新kwに落ちる。「急に目の前が真っ暗になっ**て倒れ**」等、身体文脈の共起を必須にするか、削除を推奨。 |
| 2-3 | **`うまくしゃべれない` `言葉が出にくい`（#1）** | 中 | 「緊張して人前でうまくしゃべれない」等の対人不安の訴えと衝突。救急レベル（119案内）の文面に飛ばす語としては単独で立たせるのは危険。「急に」「ろれつ」「片側しびれ」との共起前提に格下げすべき。 |
| 2-4 | **`視界がぼやけ`（#4）** | 中 | このアプリの主客層（肩こり・スマホ首・眼精疲労=既存intentあり）は「スマホの見すぎで視界がぼやける」と普通に言う。symptom系（今すぐ受診）へ飛ばすのは過剰。「急に」「片目だけ」限定に絞るべき（「片目だけ見え」「視野が欠け」は良い）。 |
| 2-5 | **`高血圧` `血圧が高`（#9）・`脳卒中` `脳梗塞`（#11）・`糖尿病`（#12）の予防相談巻き込み** | 高 | **SAFETY-REDFLAG-FIXES.md③で「転倒予防の相談を赤旗に飛ばすのは逆に有害（運動機会を奪う）」という原則が確立済み**。「高血圧予防にストレッチはいい?」「脳卒中予防に運動したい」は中高年層の頻出相談であり、この原則と真正面から矛盾する。転倒で裸の「転倒」を外し完了形に置換したのと同じ設計判断（例:「高血圧と言われ」「血圧が高いと言われ」等の当事者形への限定、あるいは「予防」共起時の除外処理）を検討しないまま裸語を提案しているのは、既存設計思想からの後退。 |

## 3. 見逃し（false negative）リスク

| # | 対象 | 問題 |
|---|---|---|
| 3-1 | **`呂律`（漢字形）が無い** | #1は「ろれつがまわら」「ろれつが回ら」のみ。IMEは「呂律が回らない」に普通に変換する。sdNormは漢字→かな変換をしない（L3011-3016で確認: 小文字化・全角半角・カタカナ→ひらがなのみ）ので**漢字「呂律」は完全に素通り**。最優先・救急レベルと自称するパターンの主要表記が抜けるのは重大。`呂律` を追加必須。同様に「顔が歪ん」（漢字の歪）も「顔がゆがむ」では拾えない。 |
| 3-2 | **活用形の詰め不足** | 「顔がゆがむ」→「顔がゆがんで(きた)」を拾えない（`ゆがむ`終止形固定）。「意識が飛んだ」→「意識が飛んで/飛びそう」を拾えない。既存kwは「気を失っ」「急に痛」のように**語幹止め**が流儀（FIXESの夜間痛設計も同じ）。`顔がゆが` `意識が飛` の形に直すべき。 |
| 3-3 | **#19 `薬を飲んでてふらつ` はほぼ発火しない** | 「飲んでて/飲んでいて/飲むと/飲んだら」の揺れ＋間に他の語（「薬を飲んでいて、たまにふらつく」）が挟まると連続部分一致は成立しない。実質死にkw。しかも根本問題として、**「血圧の薬を飲んでる」と言うユーザーは「高血圧」と言わない**ことが多く、#9の`高血圧`/`血圧が高`はどちらもヒットしない。`血圧の薬` を状態語として立てる方が実効性が高い。 |
| 3-4 | **#3 `片足だけむくん` 系は語順が固すぎる** | 実際の訴えは「右足だけパンパン」「ふくらはぎが片方だけ腫れて」「左足がむくんで熱っぽい」。「片足だけ+むくみ語」の連続形しか提案されておらず、左右指定形（右足だけ/左足だけ）が全滅。なお裸の「むくみ」を避けた判断自体は正しい（mukumi intentと衝突するため）。 |
| 3-5 | **#15 血液サラサラ系の言い回し** | 「血**を**サラサラにする薬」（血液と言わない形）が漏れ。またワーファリンは現在は処方の主流でなく、DOAC（エリキュース・リクシアナ・イグザレルト）やバイアスピリンを名指しするユーザーを取りこぼす。最低限「血をさらさら」「アスピリン」は検討対象。 |
| 3-6 | **#17 `人工関節` は「人工股関節」を拾えない** | 「人工股関節」「人工膝関節」は文字列として「人工関節」を**含まない**（間に股/膝が入る）。部分一致の落とし穴。`人工股関節` `人工膝関節` の明示追加が必要。 |
| 3-7 | #12 糖尿病の言い換え | 「血糖値が高いと言われて」「HbA1cが引っかかって」は糖尿病と言わない頻出形。`血糖値が高` の追加を検討。 |
| 3-8 | #6 `いつもとちがう激しい` | 語順固定が強すぎ（「いつもと違って激しく痛む」で不成立）。また「激しい下腹部痛」は既存の`はげしいいたみ`（連続一致）でも拾えない点の指摘自体は正しいが、提案kwも同型の脆さを持つ。`不正出血`は単独で良いkw。 |

## 4. 既存実装・安全設計思想との矛盾

| # | 問題 | 深刻度 |
|---|---|---|
| 4-1 | **B群13件の書き下ろし返答文は、現行エンジンでは表示できない。** redFlagsの返答は `answer` と `answerState` の**各1本だけ**（soudan-kb.js L1684-1687）で、sdAnswerRedFlag（index.html L3297-3308）はkw別の文面出し分けを持たない。§4の実装案「B群はkw+stateKwに追加」に従うと、全13件が汎用answerState文（「主治医の先生にOKをもらってから」）に潰れ、**#12の低血糖対処（中断して糖分を）や#14の頭を下げるポーズ回避といった安全上意味のある個別情報が全部消える**。ドラフトはこの構造制約を§0で認識している素振り（「2バケットに乗せる前提」）を見せつつ、24本の個別文面を書いており、読者（監修者）に「この文面が出る」という誤解を与える。**エンジン改修（カテゴリ別redFlagエントリ化）とセットの提案なのか、文面は将来用メモなのか、明示が必要。** | **高（提案の根幹）** |

## 5. 監修前に必ず潰すべき順（優先度つきまとめ）

1. **`しっしん` 削除**（2-1・湿疹誤爆。これだけは絶対に通してはいけない）
2. **4-1の構造問題の明示**: B群個別文面はエンジン改修なしでは出ない。改修するのか、汎用answerStateで良しとするのか、監修の前提として決める
3. **#1脳卒中の文面置き場**（4-2）: kwだけ先行追加は不可。緊急度別の第3の文面枠（crisisとredFlagsの間）が要るかの判断
4. **`目の前が真っ暗` の削除または共起条件化**（2-2・メンタル相談の否認事故）
5. **予防相談の巻き込み対策**（2-5・FIXES③の確立原則との矛盾。高血圧/脳卒中/糖尿病の裸語は当事者形に限定）
6. **`呂律`（漢字）追加＋語幹止めへの統一**（3-1・3-2。救急レベルの主要表記漏れ）
7. けいれん/てんかん・意識もうろう・透析・リウマチの追加検討（1-1〜1-5）
8. `血圧の薬`・`人工股関節/膝関節`・左右指定むくみ形などのFN補修（3-3〜3-7）
9. redflag-safety-testへの回帰ケース追補をタスク化（4-3。FIXES流の危険N/正常N実測なしで本体反映しない）

以上。本レビュー自体も含め、**本体コード（soudan-kb.js / index.html）への反映は本人監修ゲートを通過してから**。
